Standalone page — no ICS login. Pull the ICS dossier by reference, then post every container status change back through the callback. Same flow LOGICTECK uses in production.

OUTSIDE ICS APP · PUBLIC API ONLY
Permanent connection: store transferLink from the dossier. It has the reference, trucker, and the lookup, dossier, validate, and callback URLs. No shared user accounts or JWT — only X-Logicteck-Api-Key and the ICS reference. Callbacks apply only when the yard is tagged LOGICTECK.

How LOGICTECK integrates

  1. Dossier. GET /api/logicteck/booking/{reference}/dossier — full pre-forecast, photos, QR, and transferLink. Does not change status.
  2. Lookup. GET /api/logicteck/booking/{reference} — summary only, when photos are not needed.
  3. Validate. POST /api/logicteck/validate-qr with {"qrCode":"..."} — marks the QR retrieved. Once only.
  4. Callback. POST /api/logicteck/callback on every container update. Use transferLink.callbackUrl. Same eventId is ignored.
  5. ICS send. When ICS clicks Send to LOGICTECK, ICS POSTs the booking to LOGICTECK BookUrl. Save the returned reference and send it back as externalRef.
